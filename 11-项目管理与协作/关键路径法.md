# 关键路径法（Critical Path Method, CPM）

> **一句话定义**：找出决定项目总工期的最长任务链条——关键路径上任何延误都是项目延误，非关键路径的延误可以被浮动时间吸收。

## 是什么

1957 年杜邦公司与雷明顿兰德公司为化工厂停机检修开发的方法。把项目拆成带工期与依赖关系的任务网络，从起点到终点找出**总时差为零**的最长路径。核心洞察：项目工期不取决于"任务多少"，而取决于那条**不能延误的链**。

- **关键路径**：总浮动时间为 0 的任务序列，决定最早完工时间
- **浮动时间（Slack）**：非关键任务可以延误而不影响总工期的余量
- **关键链（CCPM）**：Goldratt 的增强版——考虑资源冲突与人的安全时间博弈（见约束理论）

## 核心操作

1. **列任务与依赖**：WBS 拆到可估工期的粒度，标注每个任务的前置任务
2. **估算工期**：每项给出乐观/最可能/悲观三值（可接 PERT 加权）
3. **正推算最早时间**：从起点推每个任务的最早开始/结束
4. **逆推算最晚时间**：从交付日倒推每个任务的最晚开始/结束
5. **算浮动、找关键路径**：浮动 = 最晚开始 − 最早开始；浮动为 0 的链即关键路径
6. **管理关键路径**：赶工（加资源换工期，仅对关键任务有效）或快速跟进（并行化，增加返工风险）

## 工作应用

- **多环节交付物排期**：深度报告 = 数据获取 → 建模 → 撰写 → 内部评审 → 发布。评审若在关键路径上，评审人档期没锁死 = 排期是幻觉
- **识别真正的瓶颈**：团队"很忙"但项目延误，通常是把资源投在了浮动时间大的任务上——盯住零浮动的链
- **工期谈判**：老板要提前交付，先看关键路径上哪项能压缩（加人/并行/降范围），砍非关键任务的投入无济于事

## 局限与陷阱

- 工期估算本身不准，关键路径会随实际进展漂移——要定期重算，不是一次性的
- 人的估期自带安全垫（帕金森定律：给多少用多少），关键链法用 50% 概率工期 + 缓冲池修正
- 只管时间不管资源冲突：两条路径同时抢同一个专家，纸面关键路径失真
- 小项目（<20 项任务）用 Excel 拉依赖表即可，别上重型工具
