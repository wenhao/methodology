# 看板方法（Kanban Method）

> **一句话定义**：把工作状态可视化成一列列泳道（待办/进行/完成），并给"进行中"设上限——瓶颈在墙上现形，堵在哪里一目了然。

## 是什么

源自丰田生产方式（大野耐一，1950 年代）的拉动式生产控制，David Anderson 于 2010 年前后将其提炼为知识工作方法。核心原则：**可视化工作流 + 限制在制品（WIP Limit）+ 管理流动**。

- 看板 = 墙 + 卡片 + 列（每列是一个状态）
- **WIP 限制是灵魂**：进行中列设硬上限（如"撰写中最多 2 篇"）——满了就不能开工新任务，只能先推进或搬走存量
- 拉动系统：下游有空位才允许上游放新卡——与推动系统（领导不停派活）相反

## 核心操作

1. **画工作流列**：按实际流程画（如：需求池 → 数据准备 → 分析中 → 撰写中 → 评审中 → 已发布）——先如实呈现，再优化
2. **每张卡一件事**：卡片写清任务与验收标准，一张卡=一个可交付单元
3. **设 WIP 上限**：每列（尤其中间列）设硬限制——团队吞吐量决定上限，不是意愿
4. **每日站板会**：对着看板过流动——关注"卡住的卡"（Aging）而非逐人汇报
5. **度量与改进**：周期时间（卡片从进入到完成）、吞吐量（每周完成卡数）、阻塞时长——用数据调 WIP 上限与流程

## 工作应用

- **个人任务管理**：一张"待办/今天做/进行中（上限2）/等反馈/完成"的看板，配合时间块——"等反馈"列专门存放被阻塞任务，防止其占据心智带宽
- **研究团队周会**：把覆盖公司池做成看板（每家公司一张卡：数据更新中/撰写中/评审中/已发布），周五站板会十分钟对齐全部进度——比逐个口头汇报高效一个量级
- **需求涌入管理**：老板/客户不停加需求时，拉他看板——"分析中已满 3 张上限，新需求要么等、要么换掉某张"，用系统规则代替个人拒绝
- **暴露隐性瓶颈**：如果"评审中"列常年堆积，瓶颈是评审人产能——视觉证据比口头抱怨有说服力（与约束理论联动）

## 局限与陷阱

- 有板无限=装饰品：不设 WIP 上限的看板只是便利贴墙——限制才产生流动管理
- 卡片粒度失控：一张卡干两周，看板失去节奏感——拆到 1-3 天粒度
- 不适合长周期单任务：一个季度才交付的大型建模，看板上永远一张卡——此类工作用阶段门管理，看板管日常流
- 度量异化：吞吐量成为 KPI 后，卡片被拆小刷数——度量用于改进流程而非考核个人
