# 风险管理矩阵（Risk Management Matrix / 风险概率-影响矩阵）

> **一句话定义**：把所有已识别风险按"发生概率 × 影响程度"放进矩阵，九宫格分出红黄绿区——高风险先管、备预案，低风险只登记观察。

## 是什么

项目风险管理的核心工具，ISO 31000 的落地形态。用概率（低/中/高）× 影响（低/中/高）构成九宫格，每个风险落格后决定应对策略。价值不在画格子，而在**把"隐约的不安"变成"可管理的条目"**——登记、定级、定责任人、定触发器。

## 核心操作

1. **风险识别**：头脑风暴 + 检查表（进度/资源/技术/外部四类），写成"因为X，可能导致Y"格式
2. **定级**：概率（<30% / 30-70% / >70%）× 影响（延误<1周 / 1-4周 / >4周或失败）落九宫格
3. **应对策略四选一**：
   - **规避**：改变计划绕开风险源
   - **减轻**：降低概率或影响（提前测试、备份数据源）
   - **转移**：外包、保险、条款约定
   - **接受**：低风险登记观察，高风险做应急预算
4. **每条高风险配三件套**：责任人（谁盯）、触发器（什么信号出现即启动预案）、应急预案（触发后做什么）
5. **定期复审**：风险会随项目演进搬家，每次里程碑重估九宫格

## 工作应用

- **深度报告的发布风险**：核心数据依赖单一专家口径（概率中×影响高=红区）→ 减轻：提前找第二信源交叉验证；触发器：专家改口
- **关键人依赖**：主力分析师休假撞上交付日（概率高×影响中=红区）→ 规避：交付日前两周完成初稿；预案：backup 写手与交接文档
- **数据交付依赖外部供应商**：接口变更导致数据断供（概率低×影响高=黄区）→ 转移：合同约定变更通知期；接受：本地缓存三个月历史数据

## 局限与陷阱

- 只管已知风险，未知的未知（黑天鹅）不进矩阵——需配合情景规划与事前验尸
- 定级主观打架：概率影响各拍脑袋——用团队校准会+基准比率外部视角修正
- 登记簿变坟场：写完没人复审——把风险复审绑进里程碑会议，触发器要有具体数字
- 风险厌恶过度：把黄区当红区管，预算全花在应急上——接受策略的存在就是提醒：不是所有风险都要消灭
