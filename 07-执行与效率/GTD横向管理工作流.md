# GTD（Getting Things Done）

> **一句话定义**：收集一切事务→清空大脑→横向分类处理——用外部系统承载记忆，让大脑专心思考。

## 是什么

戴维·艾伦的个人效能体系。核心哲学：**大脑是 CPU 不是硬盘**——用大脑记"该做什么"持续产生焦虑与分心（蔡格尼克效应：未完结事项持续占内存），GTD 把全部事务移入外部可信系统。

## 五步工作流

1. **收集（Capture）**：一切任务、想法、信息进入统一收件箱（一个工具，勿多）——微信里的一句"回头查下"、会议中的一个待办
2. **理清（Clarify）**：对每项问"这是什么？需要行动吗？"
   - 不需要 → 删除 / 归档 / maybe-someday（将来也许清单）
   - 两分钟能完成 → 立刻做
   - 需要行动 → 下一步行动是什么（动词开头、可执行）
3. **整理（Organize）**：进入清单体系——下一步行动清单（按场景分：@电脑/@外出/@电话）、项目清单（需多步的结果）、等待清单（已委派）、日历（定死时间的）
4. **回顾（Reflect）**：每周回顾——清空收件箱、检查各清单、校准下周重点（**GTD 的引擎，跳过即系统崩溃**）
5. **执行（Engage）**：按场景/时间/精力选任务执行

## 研究工作中的应用

- **研究碎片信息处理**：盘中突发（公告/新闻/专家消息）→ 收件箱快速捕捉不打断当前工作 → 盘后统一 clarify——**深度工作不被打断，碎片信息不丢失**
- **"下一步行动"原则改造研究任务**："写机器人板块深度报告"是项目不是行动；"拉取 12 家标的近 8 季毛利率数据做成对比表"才是行动——**动词+可完成**，启动摩擦归零
- **每周回顾对接周报制度**：回顾清单 = 研究进度 Check（PDCA 的 C 环节落地）

## 局限与陷阱

- 系统搭建容易过度工程化（工具党）——GTD 的本质是"捕捉+回顾"两个习惯，工具其次
- 周回顾缺失是系统失败的头号原因——宁可简化清单不可跳过回顾
- GTD 管"事务性工作"高效，但不解决"优先级战略"（该做什么）——与艾森豪威尔矩阵、帕累托配合使用
